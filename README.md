# Character Studio — استوديو تصميم الشخصيات

## الحالة الحالية (المرحلة 3)
منفَّذ في الكود: المشاريع المحلية (Room)، ومحرر أولي يعمل على أشكال أساسية (بيضاوي/مستطيل):
سحب وتحريك، حجم، دوران، لون، شفافية، نسخ، حذف بتأكيد، قفل، إخفاء، ترتيب الطبقات (أمام/خلف)، إعادة تسمية،
إعادة العنصر لموضعه الأصلي، تراجع/إعادة، تكبير وتحريك مساحة العمل بإصبعين دون تغيير أبعاد المشروع،
هيكل مرجعي بـ 24 نقطة تثبيت قابلة للتعديل والحفظ، تثبيت عنصر على أقرب نقطة (يتبعها عند تحريكها)، لون خلفية،
حفظ تلقائي بعد 0.8 ثانية + حفظ عند الخروج/الإيقاف + مؤشر حالة الحفظ، وإعادة فتح المشروع كما حُفظ.
المرحلة 4 (جزئيًا): طبقة بيانات الأصول المحلية (Room منفصلة عن المشاريع)، البحث والتصفية بالنمط والفئة (شاملة الفئات الفرعية)،
ومنطق المزامنة التزايدية بترقيم مفتاحي، وجداول Supabase للأصول (0002_assets.sql).
المرحلة 5 (جزئيًا): التصدير إلى PNG وJPEG وWebP بدقات 1024/2048/4096 (تظهر فقط ما تتسع له ذاكرة الجهاز)،
شفافية، تضمين الهيكل اختياريًا، معاينة، حفظ في الجهاز عبر منتقي الملفات، مشاركة عبر Sharesheet. BMP غير مدعوم (لا ترميز BMP في Android).
الإعدادات والإشعارات (جزئيًا من المرحلة 20): تذكير محلي يومي واحد (WorkManager) افتراضيًا 18:00، تعطيل/تغيير الوقت، طلب إذن Android 13+،
وصفحات مساعدة/خصوصية/شروط/معلومات (الخصوصية والشروط **مسودات تحتاج مراجعة قانونية**). نص الإشعار ثابت حاليًا (تعديله من لوحة التحكم لاحقًا).
**غير منفَّذ بعد من المرحلة 5:** أبعاد مخصصة، استبعاد طبقات محددة من التصدير، Sprite Sheets.
**غير منفَّذ بعد من المرحلة 4:** شاشة المكتبة، تحميل الصور من Cloudinary والتخزين المؤقت، إضافة الأصل إلى المحرر،
التنفيذ الفعلي لـ AssetRemoteSource (يحتاج حسابات المستخدمين)، لوحة رفع الأصول.
**غير منفَّذ بعد:** سحب الطبقة لإعادة ترتيبها (حاليًا أزرار للأمام/للخلف)، تحديد عدة عناصر، أصول الشخصيات (مكتبة الأصول)،
التصدير، الحسابات والمزامنة، النقاط (واجهة)، الإعلانات، الدفع، لوحة الإدارة.
**لم يُبنَ المشروع ولم تُشغَّل الاختبارات** — أول تشغيل سيكون عبر GitHub Actions (انظر أدناه).

## ربط التطبيق بالمكتبة (مرة واحدة)
في GitHub → Settings → Secrets and variables → Actions → **Variables** أضف ثلاثة متغيرات (قيم عامة وليست أسرارًا):
`SUPABASE_URL` و`SUPABASE_ANON_KEY` (المفتاح anon/publishable فقط) و`CLOUDINARY_CLOUD_NAME`. ثم أعد تشغيل Android CI.
بدونها تعمل المحررات كلها، وتعرض المكتبة رسالة «غير مضبوط». شغّل `0007_public_library.sql` ليقرأ التطبيق الأصول المنشورة بلا حساب.

## التوقيع وتحديث التطبيق فوق نسخة سابقة
- بناء debug: يُوقَّع بمفتاح ثابت داخل المستودع (`app/debug.keystore`) فتتحدّث كل النسخ فوق بعضها.
  المفتاح عام (كلمة المرور android) → للاختبار فقط. بصمات هذا المفتاح تظهر في سجل خطوة "Show debug signing fingerprints".
- بناء release: يعمل تلقائيًا فقط إن أضفت في GitHub → Settings → Secrets → Actions:
  `RELEASE_KEYSTORE_BASE64` (ملف jks بصيغة base64) و`RELEASE_KEYSTORE_PASSWORD` و`RELEASE_KEY_ALIAS` و`RELEASE_KEY_PASSWORD`.
  لا تُرسل هذه القيم في أي محادثة. نتيجته Artifact باسم character-studio-release-apk مع SHA256SUMS.txt.
- الانتقال من نسخة موقّعة بمفتاح آخر إلى هذا المفتاح يتطلب **حذف النسخة المثبّتة مرة واحدة** (يحذف مشاريع الاختبار عليها).

## العمل من الهاتف
1. أنشئ مستودعًا **خاصًا** على GitHub وارفع محتويات هذا المجلد (Add file → Upload files من المتصفح).
2. تبويب Actions → Android CI → Run workflow.
3. عند النجاح: افتح تشغيل الـ workflow وحمّل Artifact باسم `character-studio-debug-apk` ثم ثبّته (APK تجريبي موقّع بمفتاح debug).
4. عند الفشل: انسخ سجل الخطأ وأرسله لي لإصلاحه.

لا يوجد Gradle Wrapper في المستودع (لا يمكن توليده دون شبكة)؛ الـ workflow يثبّت Gradle 8.9 بنفسه.
ولإنشاء wrapper لاحقًا من Codespaces: `gradle wrapper --gradle-version 8.9`.

## applicationId
القيمة الحالية `app.characterstudio` مؤقتة. **غيّرها قبل أول إصدار تنشره** إن أردت اسمًا آخر، لأنها لا تتغير بعده.

## الأسرار
لا تُرفع أي مفاتيح. مفاتيح التوقيع والخدمات تُضاف لاحقًا في GitHub → Settings → Secrets. ملف seed_admin.sql لا يحتوي أسرارًا.
