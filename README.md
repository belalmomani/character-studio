# استوديو الشخصيات ثلاثية الأبعاد (3D Human Character Studio)

تطبيق Android أصلي (Kotlin + Jetpack Compose) لإنشاء شخصية بشرية ثلاثية الأبعاد من صورة، بواجهة عربية RTL.

> **الحالة: الإصدار 0.4.0 (المراحل 1 إلى 4: الصورة، العارض، التصدير، عميل الخادم).** المشروع لم يُبنَ ولم تُنفَّذ اختباراته بعد، والعارض لم يُجرَّب على جهاز حقيقي (انظر "حالة التحقق").

## ما هو منفَّذ فعلًا في هذه النسخة

- اختيار صورة من منتقي الصور النظامي، أو التقاطها بتطبيق الكاميرا عبر النظام (بلا إذن كاميرا ولا وصول واسع للملفات).
- تصغير الصور الكبيرة أثناء فك الترميز، وتصحيح اتجاه EXIF.
- مراجعة الصورة مع تدوير يمين/يسار، واستبدالها أو إلغاء العملية.
- حذف الصور المؤقتة عند الإلغاء والاستبدال وإغلاق التطبيق وبداية الجلسة التالية.
- نموذج حالات معالجة حقيقي (جاهز للرفع، رفع، إنشاء، تنزيل، تحقق، اكتمال، فشل، إلغاء)، ولا توجد نسب تقدم مختلقة.
- فاصل `ImageTo3DService` لتبديل المزود لاحقًا، وتنفيذ افتراضي `NotConfiguredImageTo3DService` يعلن بصراحة أنه لا مزود مربوطًا ولا يرفع شيئًا.
- `GlbValidator` يفحص ترويسة GLB وجزء JSON ويبلغ عن وجود مواد/هيكل/حركات/Morph Targets (فحص نصي سريع وليس فحص جودة).
- شاشة الخصوصية.
- **عارض GLB (Filament)**: زر "عرض ملف GLB موجود" يفتح ملفًا من الهاتف، فيُنسخ إلى مجلد مؤقت ويُفحص ثم يُعرض بمحرك Filament: تدوير بالسحب وتكبير بالإصبعين وإضاءة وإعادة ضبط الكاميرا.
- تشغيل الحركات المضمّنة في الملف (إن وُجدت): اختيار الحركة، إيقاف مؤقت، السرعة، التكرار. لا تُعرض عناصر التحكم إن لم يحتوِ الملف على حركات.
- حد حجم الملف 80 ميغابايت، ويُحذف الملف عند الخروج من المعاينة أو إغلاق التطبيق.

- **تصدير GLB**: زر "تصدير" في المعاينة يفتح شاشة تعرض الحجم وفحصًا نصيًا (مواد/هيكل/حركات) وتحذيرًا إن كان النموذج ثابتًا، مع اسم ملف قابل للتعديل. الحفظ يتم عبر نافذة النظام لاختيار المكان (بلا صلاحيات تخزين). لا تظهر رسالة نجاح إلا بعد قراءة الملف المكتوب والتأكد أن حجمه يطابق الأصل، ويُحذف الملف الناقص عند الفشل. يُحفظ الملف كما فُتح دون تعديل.
- لا يوجد إلغاء للتصدير أثناء الحفظ (الملفات صغيرة عادة)، ولم يُختبر الملف الناتج في Unity أو Unreal أو Godot.

- **الإعدادات وخادم التحويل (الإصدار 0.4.0)**: شاشة إعدادات لعنوان الخادم (HTTPS فقط) ورمز اختياري مشفّر بـ Android Keystore، وزر "اختبار الاتصال" يستدعي `/v1/health` دون إرسال صور.
- **موافقة قبل الرفع**: نافذة تعرض عنوان الخادم وتطلب موافقة صريحة في كل مرة قبل إرسال الصورة. لا يُرسَل شيء بدونها.
- **عميل HTTP حقيقي** (`ServerClient` و`HttpImageTo3DService`) وفق العقد في `docs/SERVER_CONTRACT.md`: رفع، ثم متابعة حالة المهمة، ثم تنزيل GLB وفحصه وفتحه في المعاينة. عند الإلغاء أو الفشل يُحذف الملف الجزئي ويُطلب من الخادم حذف المهمة.
- **لا يوجد خادم مرفق، ولم يُجرَّب العميل على خادم حقيقي.** بدون ضبط خادم تظهر رسالة صريحة بأنه غير مضبوط ولا يُرسَل شيء.

القيود: العارض يعرض ما في الملف فقط. لا ينشئ هيكلًا عظميًا ولا حركات، ولا يضمن سلامة الأوزان. زوايا العرض الجاهزة (أمام/خلف/جانب) والخلفية والإضاءة القابلة للتبديل غير منفَّذة بعد.

## ما هو غير منفَّذ بعد (ولا يظهر في الواجهة)

إزالة الخلفية، قص الصورة، خادم التحويل نفسه (العميل جاهز، لكن لا يوجد خادم مرفق ولا قرار نهائي بالعتاد والترخيص)، التخصيص، الهيكل العظمي، الحركات، التعابير، الصوت، تصدير glTF وFBX، الإعدادات، Start.io، Firebase (غير مطلوب حاليًا).
لا تُعرض أزرار لهذه الميزات إلى أن تُنفَّذ.

## حالة التحقق (صريحة)

| البند | الحالة |
|---|---|
| بناء Debug | **لم يُنفَّذ**: بيئة التطوير التي كُتب فيها المشروع لا تصل إلى `dl.google.com` ولا `maven.google.com` ولا `plugins.gradle.org` (رفض الوكيل بـ 403) وليس فيها Android SDK |
| الاختبارات `GlbValidatorTest` و`AnimationControllerTest` و`FileNamesTest` و`StreamCopyTest` | كُتبت ولم تُشغَّل |
| العارض على جهاز أو محاكي | **لم يُجرَّب**: واجهات Filament استُخدمت اعتمادًا على مصدر Google الرسمي دون ترجمة |
| بناء Release / AAB | لم يُنفَّذ، ولا يوجد مفتاح توقيع |
| اختبار التحديث فوق نسخة سابقة | لم يُنفَّذ (لا توجد نسخة سابقة) |
| تجربة على جهاز | لم تُنفَّذ |
| رفع إلى GitHub | لم يُنفَّذ، لا ربط متاح |

قد تظهر أخطاء ترجمة عند أول بناء لأن الشيفرة لم تُترجَم. أرسل لي نص الأخطاء لإصلاحها.

## البناء

المتطلبات: Android Studio حديث (Ladybug أو أحدث)، JDK 17+، Android SDK 35.

1. افتح مجلد المشروع في Android Studio ودع Gradle يزامن المشروع.
2. شغّل `./gradlew :app:testDebugUnitTest` للاختبارات.
3. شغّل `./gradlew :app:assembleDebug` لبناء APK للاختبار (`app/build/outputs/apk/debug/`).

## البنية

```
app/src/main/java/com/humanstudio3d/
  MainActivity.kt
  domain/   ProcessingModels, ImageTo3DService, GlbValidator
  data/     ImageRepository (ملفات مؤقتة فقط)
  ui/       CharacterViewModel, AppNav, screens/, components/, theme/
```

## القرارات المعلقة

انظر `docs/DECISIONS.md` (مزود إنشاء النماذج، سقف التكلفة، applicationId، التخصيص).

## الإصدارات

- `applicationId` الحالي `com.example.humanstudio3d` **للتطوير فقط وغير معتمد**. يجب اعتماد الاسم النهائي قبل أي نسخة موزعة، وبعد اعتماده لا يتغير.
- `namespace` الداخلي `com.humanstudio3d` مستقل عن `applicationId`.
- كل إصدار: زِد `versionCode`، حدّث `versionName`، دوّن التغييرات في `CHANGELOG.md`، واحتفظ بنفس مفتاح التوقيع.
- مفاتيح التوقيع والأسرار لا تُرفع إلى المستودع (`.gitignore` يمنعها).

## الخصوصية

لا مكتبة سحابية، لا Firebase Storage/Firestore، لا حسابات، لا تحليلات. الصور في `cacheDir` فقط وتُحذف. أي رفع لخدمة خارجية يتطلب موافقة صريحة، ومفاتيح API السرية تبقى في خادم وسيط وليس في APK.
